# Android setup / Настройка Android

The checked-in manifest already contains the least-privilege permission set.
The notes below explain why each permission exists and how transitive write
permissions are rejected.

В репозитории уже лежит манифест с минимальным набором разрешений. Ниже описано,
зачем нужно каждое из них и как блокируются транзитивные разрешения на запись.

## `android/app/src/main/AndroidManifest.xml`

The effective block inside `<manifest>`, above `<application>`, is:

```xml
<!-- Network access: connect to RouterOS and read current network/Wi-Fi state. -->
<uses-permission android:name="android.permission.ACCESS_WIFI_STATE"/>
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE"/>
<uses-permission android:name="android.permission.INTERNET"/>

<!-- Android treats SSID/BSSID as location-sensitive Wi-Fi data. -->
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"/>
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION"/>

<!-- Reject write permissions declared transitively by wifi_iot. -->
<uses-permission android:name="android.permission.CHANGE_WIFI_STATE"
    tools:node="remove"/>
<uses-permission android:name="android.permission.CHANGE_NETWORK_STATE"
    tools:node="remove"/>
<uses-permission android:name="android.permission.WRITE_SETTINGS"
    tools:node="remove"/>
```

`NEARBY_WIFI_DEVICES` is intentionally absent. The app reads the current link;
it does not scan for nearby networks, perform Wi-Fi Direct/RTT operations, or
manage connections. If a future scanner is implemented, its permission model
must be reviewed separately before that feature is enabled.

The custom `com.slipko.wifi_apk.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` that
appears in a built APK is generated by AndroidX, is signature-protected and does
not grant access to Android settings.

## Runtime permission

Location permission must be **granted at runtime** and **Location services turned
on**, otherwise Android hides SSID/BSSID. The app requests it when needed; it
does not request background location and never reads physical coordinates.

## Build config notes

- `minSdkVersion`: 21+ is fine; `flutter_secure_storage` wants 18+.
- Uses JDK 17 to build (see main README).

## iOS (later)

iOS needs the *Access WiFi Information* entitlement and
`NSLocationWhenInUseUsageDescription` in `Info.plist`. RSSI access is more
restricted than on Android — tracked in TODO under v0.3.
