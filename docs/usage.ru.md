## 1. Зачем это приложение

Любой Wi-Fi-анализатор на телефоне показывает половину линка: **как телефон
слышит точку доступа**. Этой половины недостаточно. Телефон может показывать
комфортные −50 dBm, а точка слышать телефон на −75 dBm — точка кричит, телефон
шепчет, и связь заикается только в одну сторону.

Приложение читает **вторую половину** прямо с MikroTik (CAPsMAN или обычный
Wi-Fi), **только по MAC твоего устройства**, и показывает обе половины рядом
вместе с разницей между ними:

## 2. Что нужно перед началом

- Android-телефон и APK со [страницы релизов](../../../releases/latest).
- MikroTik с CAPsMAN или раздающий Wi-Fi сам, доступный с этого телефона.
- Пользователь RouterOS **только для чтения** (следующий раздел).
- Телефон подключён к тому Wi-Fi, который проверяем (не мобильный интернет) —
  приложение находит твою станцию по IP на роутере.

На роутер ничего ставить не нужно, и в его конфигурации ничего менять не
требуется, кроме включения того сервиса, через который подключаешься.

## 3. Подготовка MikroTik

Подробно — [mikrotik-readonly-user.md](mikrotik-readonly-user.md). Кратко: группа
без `write` плюс нужный сервис:

```
/user group add name=monitor policy=read,api,rest-api,ssh,test
/user add name=monitor group=monitor password=СМЕНИ_МЕНЯ

/ip service enable www-ssl     # REST  (RouterOS 7.1+)
/ip service enable api         # бинарный API (RouterOS 6 и 7)
                               # SSH обычно уже включён
```

Поддерживаются три транспорта, и можно спокойно оставить **Авто**:

| Транспорт | Порт | Что нужно | Замечания |
|-----------|------|-----------|-----------|
| REST | 443 | RouterOS 7.1+, `www-ssl` | Самый быстрый, пробуется первым |
| Бинарный API | 8728 / 8729 | сервис `api` / `api-ssl` | Работает на RouterOS 6 |
| SSH | 22 | политика `ssh` у пользователя | Ничего включать не надо; выполняются только `print` и `monitor once` |

SSH — спасательный вариант для роутера, где REST нет, а сервис API выключен. Он
чуть медленнее (на каждое чтение — команда в консоли, около 120 мс на опрос
против 60 мс по REST) и остаётся только чтением: приложение само собирает каждую
команду из пути меню и `print` / `monitor once`, всё остальное отклоняет.

## 4. Первый запуск и разрешения

Приложение один раз попросит **геолокацию**. Это не слежка: Android отдаёт
приложениям SSID, BSSID и RSSI текущей сети только при выданном разрешении на
местоположение. Откажешь — IP, шлюз и данные с роутера всё равно будут видны, а
имя сети и точка доступа останутся скрытыми.

Фоновую геолокацию приложение не запрашивает и физические координаты не читает.
Все разрешения, позволяющие менять Wi-Fi или настройки сети, явно исключены —
подключиться, отключиться или забыть сеть приложение не может физически.

## 5. Подключение

Заполняем форму на первом экране:

- **Host / IP** — адрес роутера, например `192.168.88.1`.
- **Пользователь / Пароль** — тот, что только для чтения.
- **Транспорт** — `Авто (REST → API → SSH)`, если нет причин выбирать вручную.
- **Порт** — пусто для стандартного; поле доступно только когда транспорт
  выбран явно (нестандартный порт принадлежит одному протоколу).
- **TLS** — включён для HTTPS/api-ssl. Самоподписанные сертификаты принимаются —
  в локальной сети это норма.

**Несколько роутеров.** Кнопка *Добавить ещё роутер* собирает список: например,
центральный CAPsMAN плюс отдельные точки. Приложение опрашивает все и ведёт
телефон при роуминге между ними; на дашборде видно, какая точка обслуживает
сейчас. Пароли уходят в Android Keystore, не в открытые настройки.

**Роутера под рукой нет?** Нажми *Просто смотреть свою сеть (без роутера)* —
режим только телефона: всё, что телефон знает про линк (RSSI, диапазон, канал,
стандарт, безопасность, скорости, пинг) плюс аудит по данным телефона. Карточка
точки скрыта — читать её неоткуда.

## 6. Как читать дашборд

**Строка состояния** (сверху). Зелёная — все метрики в пределах твоих целей.
Жёлтая — перечисляет, что именно вышло за цель (сигнал телефона, сигнал точки,
любой из SNR, асимметрия).

**Сводка подключения.** SSID, диапазон, канал и частота, обслуживающая точка,
твой IP и BSSID, используемый транспорт и **плашка Δ**.

> Плашка Δ — смысл всего приложения: разница между тем, как точка слышит тебя, и
> тем, как ты слышишь точку. **Нажми на неё** — получишь понятный вывод и
> советы, например «точка громче телефона: снизь мощность точки или подойди
> ближе». Это типовое лечение односторонней связи.

**Телефон → слышит точку** (зелёная карточка). RSSI, SNR, скорости линка
(tx/rx), поколение 802.11, тип защиты, канал.

**Точка → слышит телефон** (синяя карточка). Данные таблицы регистрации по твоему
MAC: сигнал, SNR (измеренный, а где таблица его не отдаёт — оценка по уровню шума
радио, помечена как оценка), скорости tx/rx, CCQ, сигнал по цепочкам, скорость по
счётчикам байт, время на этой точке и счётчик роуминга за сессию.

**Здоровье роутера.** Модель, версия RouterOS, загрузка CPU, аптайм.

**Пинг.** Настоящий ICMP до шлюза на каждом опросе. Всплески задержки или потери
при сильном сигнале — признак помех или загруженной точки.

**Диагностика соединения.** Это отдельная проверка из шести замеров, а не
бесконечно меняющийся вывод. Нажми *Запустить диагностику* в нужном месте:
карточка покажет прогресс, затем зафиксирует результат вместе с именем точки и
временем завершения. По нажатию на вывод откроются факты, вероятные причины и
советы. После подключения или роуминга приложение может запускать ту же
проверку автоматически, но сначала ждёт стабилизации линка, чтобы переходные
значения не исказили результат. Во время ожидания кнопка *Запустить сейчас*
пропускает задержку; активный замер можно отменить или повторить.

**Мини-график.** Обе стороны во времени: ходи по квартире или офису и смотри, где
всё проваливается.

По любой цифре можно **нажать** — откроется объяснение, что это и что делать.

## 7. Какие цифры считать нормальными

| Метрика | Хорошо | Терпимо | Плохо |
|---------|--------|---------|-------|
| Сигнал (любая сторона) | −30…−60 dBm | −60…−70 dBm | ниже −75 dBm |
| SNR | выше 25 dB | 15…25 dB | ниже 15 dB |
| Асимметрия Δ | меньше 6 dB | 6…12 dB | больше 12 dB |
| Пинг до шлюза | меньше 20 мс | 20…80 мс | больше 80 мс или потери |

Большая Δ при *сильном* сигнале телефона — классический случай «точка слишком
громкая»: телефон отлично слышит далёкую точку и продолжает за неё держаться, а
его собственная передача не доходит. Снижение мощности точки или signal-range в
access-list лечит больше проблем, чем когда-либо лечило повышение мощности.

## 8. Типовые задачи

**Обход помещения.** Подключись, нажми ⏺ *Запись*, пройди маршрут медленно, в
проблемных местах постой несколько секунд, ⏹ — стоп. Сессия попадёт в *Историю*,
оттуда выгружается в CSV.

**Разбор односторонней связи.** Встань там, где жалуются, посмотри на Δ, нажми на
неё, выполни совет. Проверь снова — то же место, тот же интервал опроса.

**Проверить телевизор, ноутбук или телефон гостя.** ⋮ → *Устройства*: все
станции, подключённые сейчас, дополненные IP и именем из DHCP-lease. Выбери
любую — увидишь, как точки слышат *её*. Удобно для устройств, на которые
анализатор не поставишь.

**До и после правки конфига.** Прогони аудит Wi-Fi, сам примени исправления на
роутере, прогони аудит снова, выгрузи оба в PDF.

## 9. Аудиты

Три отчёта только на чтение, все из ⋮:

- **Аудит Wi-Fi** — радио и настройки Wi-Fi: план каналов (1/6/11), пересечение
  каналов между твоими же точками, ширина на 2,4 ГГц, страна/регуляторка,
  мощность, защита у тех конфигураций, которые реально применены к работающему
  радио, изоляция клиентов, политика против «залипания» клиентов.
- **Системный аудит** — здоровье и безопасность: синхронизация NTP, доступное
  обновление RouterOS, FTP/Telnet, открытость сервисов управления, учётка
  `admin` по умолчанию, входной firewall, исчерпание IP-пула.
- **Аудит сети (телефон)** — в режиме без роутера: сигнал, диапазон, канал
  2,4 ГГц, защита, поколение 802.11 и скорость линка относительно сигнала.

<img src="screenshots/audit.png" width="300" alt="Экран аудита">

Каждая находка двуязычная, с уровнем важности, указанием *где* и *что делать*.
**Пройденные проверки тоже показываются** — отчёт из одних проблем не говорит,
что уже сделано правильно. Кнопка *Экспорт PDF* отдаёт отчёт в шаринг.

Аудит намеренно осторожен и честно говорит, когда не уверен:

- он смотрит на **рабочее состояние** (`current-channel`), а не на поле
  конфигурации, потому что CAPsMAN перекрывает локальные настройки;
- конфигурация CAPsMAN, не применённая к работающему радио, не считается живым
  риском;
- сервис называется «открытым» только когда нет ни ACL по адресу, ни правила
  firewall по умолчанию запрещающего;
- отключённая учётка `admin` — это **ОК**, а не находка;
- если меню не удалось прочитать, отчёт пишет **«Отчёт неполный: не прочитано
  меню — N»** и пропускает зависящие от него проверки: нечитаемый firewall не
  должен превращаться в «firewall отсутствует».

## 10. История и запись

⏺ в верхней панели пишет каждый опрос в локальную базу SQLite. ⋮ → *История* —
список сессий; открой любую, чтобы посмотреть замеры, выгрузить CSV или удалить.
Удаление касается только данных самого приложения.

## 11. Цели и оповещения

*Настройки → Цели* задают минимально приемлемые сигнал и SNR и максимально
терпимую асимметрию. Строка состояния судит именно по этим числам.

Иконка колокольчика в панели включает **оповещения**: при выходе за цель
приложение пищит (880 Гц) и вибрирует — можно идти с телефоном в руке и слушать,
а не смотреть. Звук генерируется в памяти: ни медиафайлов, ни разрешения на
уведомления.

## 12. Настройки

| Настройка | Смысл |

## 14. Диагностика LTE-сигнала

⋮ → *Диагностика LTE* открывает полностью отдельный инструмент для MikroTik с
LTE-модемом. Он не использует Wi-Fi-измерения телефона, а телефон не обязан быть
подключён именно к Wi-Fi этого MikroTik. Достаточно сетевого доступа к роутеру по
одному из поддерживаемых транспортов управления.

Укажи адрес, логин и пароль read-only пользователя. Режим *Авто* пробует REST →
бинарный API → SSH; также можно явно выбрать транспорт, TLS и нестандартный
порт. Поле *LTE-интерфейс* можно оставить пустым — приложение само выберет
работающий интерфейс; либо укажи имя вроде `lte1`. Профиль хранится в Keystore
устройства отдельно от Wi-Fi-профилей. Старый профиль, созданный SSH-only
версией, после обновления останется SSH-профилем.

Приложение выполняет только следующие команды чтения:

```
/interface lte print
/interface lte monitor <интерфейс> once
/system resource print
```

Дашборд обновляется раз в три секунды и показывает:

- **RSRP** — принятую мощность опорного LTE-сигнала, главный показатель покрытия
  и уровня на антенне;
- **RSRQ** — качество опорного сигнала с учётом помех и нагрузки сектора;
- **SINR** — полезный сигнал относительно помех/шума, сильно влияет на скорость;
- **RSSI/CQI**, если модем их отдаёт;
- диапазон, ширину канала, EARFCN, PCI, eNodeB/сектор и Cell ID;
- минимум/среднее/максимум по последним 60 замерам.

Вердикт специально разделяет **слабый, но чистый** сигнал (вероятнее направление
антенны, высота, кабель или разъёмы) и **достаточно сильный, но шумный**
радиоканал (вероятнее помехи, отражения или нагрузка сектора). Нажми на RSRP,
RSRQ, SINR, RSSI или CQI, чтобы увидеть пороги и объяснение.

### Мастер юстировки антенны

На LTE-дашборде нажми *Запустить мастер юстировки антенны*. Выбери небольшое
физическое перемещение, которое можешь одинаково повторять — например, одно
деление на кронштейне. Приложение не знает абсолютный азимут и угол антенны,
поэтому координаты X/Y означают подтверждённые оператором **шаги**, а не градусы.

1. Не двигай тарелку и зафиксируй исходную точку.
2. Выполни предложенное относительное перемещение и нажми *Переместил — измерить*.
3. Приложение ждёт четыре секунды стабилизации и собирает шесть свежих значений.
   В это время не двигай антенну.
4. Повторяй предложенные пробы. Мастер продолжает движение при улучшении, а
   затем проверяет ещё не посещённые соседние позиции вокруг подтверждённой
   лучшей точки.
5. Когда соседние точки не дают заметного улучшения, вернись по указанному
   числу шагов, уменьши физический шаг вдвое и запусти точный проход.

Три живых графика отдельно показывают RSRP, RSRQ и SINR. Итоговый рейтинг —
только помощник навигации: при очень слабом RSRP он сильнее учитывает покрытие,
а после достижения рабочей мощности отдаёт приоритет SINR/RSRQ, добавляет CQI,
если он доступен, и штрафует нестабильные пики. Сырые метрики всё равно остаются
на экране. Смена диапазона или обслуживающей соты отмечается отдельно, потому
что изменение рейтинга в этот момент могло вызвать переключение, а не только
движение антенны.

Контрольные точки сохраняются при выходе из мастера и повторном входе, но
текущая сетка юстировки очищается при отключении от LTE-роутера. Иконка повтора
удаляет точки после подтверждения и снимает новую исходную позицию.

### История LTE-записей

Нажми красную кнопку записи на LTE-дашборде, чтобы начать постоянную сессию.
Каждый успешный опрос LTE будет сохраняться локально; нажми Stop или отключись,
чтобы закончить запись. Через меню дашборда открой *Историю LTE*: там сессию
можно переименовать, изучить, экспортировать или удалить. Отметь ровно две
сессии, чтобы сравнить средние значения и разброс RSRP/RSRQ/SINR/RSSI/CQI,
диапазоны и обслуживающие соты.

В масштабе 1× живой или сохранённый график целиком помещается по ширине.
Используй −/+, ползунок 1×…20× или жест двумя пальцами, чтобы растянуть график,
затем двигай его по горизонтали. Точки при этом не отбрасываются — меняется
только масштаб отображения. История содержит только созданные приложением
замеры и удаляется с экрана истории.

RouterOS часто добавляет в ответ IMEI, IMSI и ICCID. Приложение не моделирует,
не показывает, не пишет в журнал и не хранит эти идентификаторы: они
отбрасываются сразу после разбора ответа.

## 15. Отчёт в поддержку

⋮ → *Отчёт в поддержку* создаёт диагностические материалы, которые при
необходимости можно отправить разработчику. Удалённого сбора и автоматической
загрузки нет. Временный архив появляется только после нажатия *Создать и
отправить ZIP* и содержит:

- `report.txt` — читаемое состояние приложения/телефона, текущие показатели с
  двух сторон и результат диагностики связи;
- `report.json` — те же факты в структурированном виде;
- `events.log` — до 200 контролируемых событий подключения и жизненного цикла,
  которые хранятся только в памяти до перезапуска или ручной очистки;
- `README.txt` — памятку о приватности.

SSID, BSSID, MAC, IP и имена роутеров/точек по умолчанию маскируются. Если для
воспроизведения проблемы они нужны, их можно включить отдельным переключателем.
Пароли, токены, приватные ключи, сырые ответы RouterOS и полные списки других
клиентов не добавляются никогда — даже с этим переключателем. Перед отправкой
можно проверить `report.txt`. Если ZIP неудобен, есть кнопка *Копировать отчёт*.

## 16. Что делать, если не работает

| Симптом | Причина и лечение |
|---------|-------------------|
| «Не подключено к Wi-Fi», хотя подключено | Не выдана геолокация или телефон на мобильном интернете. Выдай разрешение; приложение также судит по IP — проверь, что адрес локальный. |
| Карточка точки пустая, «точка не под управлением MikroTik» | Телефон подключился к точке, которой этот роутер не управляет. Добавь и её роутер (*Добавить ещё роутер*). |
| Ошибка аутентификации | Неверные логин/пароль или у группы нет политики под транспорт (`rest-api`, `api`, `ssh`). |
| «REST API недоступен» | RouterOS 6 или выключен `www-ssl`. Переключи транспорт на Авто, API или SSH. |
| Роутер недоступен | Неверный хост или ты не в его сети. Сверься со шлюзом в сводке. |
| Значения обновляются медленно | Тротлинг сканирования Wi-Fi в Android — см. статью в Справке или увеличь интервал опроса. |
| SNR помечен как оценка | Таблица регистрации не отдаёт SNR (типично для CAPsMAN); он выведен из измеренного уровня шума радио. |
| По SSH вообще ничего | Группе пользователя нужна политика `ssh`; проверь, что `/ip service` пускает твою подсеть. Для LTE также можно выбрать REST или бинарный API. |
| LTE пишет, что интерфейс не найден | Проверь, что в `/interface lte print` есть включённый интерфейс, либо очисти/исправь необязательное имя интерфейса в форме LTE. |
| LTE зарегистрирован, но метрики пустые | Подожди завершения регистрации; некоторым связкам модема и RouterOS нужна актуальная прошивка модема, чтобы отдавать радиометрики. |
| Аудит пишет «Отчёт неполный» | Эти меню не прочитались — обычно сессия оборвалась, пока приложение было в фоне (оно переподключается, просто прогони снова), или у пользователя нет на них прав. |

## 17. Чего приложение не делает никогда

- **На роутере:** никакой записи. Пути записи в коде нет — интерфейс транспорта
  умеет только читать, а SSH-транспорт вдобавок разрешает лишь `print` и
  `monitor once` и отклоняет всё остальное. Читается только нужное: ARP/DHCP для
  IP→MAC, таблица регистрации по твоему MAC, меню Wi-Fi и системные — для
  аудита, либо LTE-интерфейс/monitor в отдельном LTE-инструменте. Идентификаторы
  модема/SIM из ответа RouterOS отбрасываются, а не сохраняются.
- **На телефоне:** приложение читает Wi-Fi-модуль, но не меняет, не подключает,
  не отключает и не забывает сети — разрешение на это явно удалено из манифеста.
  К контактам и медиа доступа нет. Хранит только своё: пароли роутеров в
  Keystore, настройки, историю замеров и временный диагностический ZIP,
  создаваемый только по команде пользователя. Изнутри приложения удаляются
  только его собственные данные.
